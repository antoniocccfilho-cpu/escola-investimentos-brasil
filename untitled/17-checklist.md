# Checklist de conformidade acadêmica

Esta matriz traduz as exigências do professor em **evidências documentáveis**. Uma seção escrita não significa que a funcionalidade correspondente foi implementada ou testada.

## Conteúdo obrigatório no GitBook

| Exigência | Onde consultar | Situação documental |
| --- | --- | --- |
| Nome do projeto e equipe | [Introdução](01-introducao.md) | Registrado; distribuição de papéis pendente |
| Problema, contexto e público | [Problema](02-problema-e-oportunidade.md), [Público-alvo](03-publico-alvo.md) | Hipótese descrita e dado externo fundamentado; pesquisa própria pendente |
| Solução e funcionalidades | [Solução](04-solucao-proposta.md), [Funcionalidades](05-funcionalidades.md) | Documentadas com limites; retestes necessários |
| IA e automação | [IA](07-inteligencia-artificial.md), [Uso de IA](15-uso-de-ia.md) | Processo descrito; prompts e resultados reais a consolidar |
| Dados utilizados | [Dados](08-dados-utilizados.md) | Inventário inicial; armazenamento real a verificar |
| Tecnologias e justificativas | [Tecnologias](09-tecnologias.md) | Ferramentas centrais identificadas; stack detalhada a confirmar |
| Viabilidade e escopo | [Viabilidade](10-viabilidade-escopo-limitacoes.md) | Escopo e riscos descritos; custos reais pendentes |
| Impactos, inclusão, ética e LGPD | [Impactos](13-impactos-esperados.md), [Ética](14-etica-lgpd-seguranca.md) | Impactos como hipóteses; conformidade não atestada |
| Conclusão e fontes | [Conclusão](19-conclusao.md), [Referências](18-referencias.md) | Texto preparado; revisão final do grupo pendente |

## Plano de trabalho obrigatório

A ficha exige **ordem, atividade, início, fim, responsável e percentual executado em cada revisão**. A [página de cronograma](12-cronograma.md) contém a estrutura inicial, mas os campos desconhecidos **não devem receber números inventados**.

- [ ] Conferir quem é responsável por cada tarefa e registrar divisão do grupo.
- [ ] Preencher início e término das atividades com dados reais.
- [ ] Informar percentuais por RT com evidências de execução.
- [ ] Confirmar situação de submissão das RT01–RT03.
- [ ] Concluir preparação da **RT04 de 17/11/2026**.
- [ ] Confirmar qual sessão de banca cabe ao grupo: **24/11 ou 01/12**.

## Demonstração e testes

- [ ] Abrir o app e concluir um percurso funcional sem link quebrado.
- [ ] Identificar visivelmente dados demonstrativos e conteúdo indisponível.
- [ ] Separar a Saga do Dinheiro como curso independente na versão de apresentação.
- [ ] Validar pedagogicamente a Aula 4 antes de produzir a Aula 5.
- [ ] Registrar testes com data, ambiente, resultado e evidência.
- [ ] Preparar vídeo/capturas de contingência para a banca.
- [ ] Ensaiar apresentação de **40 a 50 minutos**, verificando as regras da ficha e presença da equipe.
- [ ] Fazer auditoria geral como aluno **após produzir as aulas**, conforme o planejamento vigente.

## Modelo de registro de revisão

| Campo | Preenchimento exigido |
| --- | --- |
| RT e data | Ex.: RT04 — 17/11/2026 |
| Versão / commit | Identificação no GitHub ou Base44 |
| Atividade e responsável | Nome e ação verificável |
| Início, fim e percentual | Valores reais ou “não apurado” |
| Evidência | Captura, vídeo, link, teste ou entrega |
| Correção/decisão | O que mudou e por quê |
| Aprovação | Quem conferiu e quando |

{% hint style="warning" %}
**Este checklist não está integralmente concluído.** As pendências assinaladas são justamente o que a equipe deve validar para afirmar atendimento aos requisitos do professor.
{% endhint %}
